# Escalation-rule design aid (tuning set only)

Generated by `scripts/a2_tuning_analysis.py` from the Assignment 1 per-ticket answers, **tuning set only** (98 odd-row tickets). Escalated tickets take `qwen2.5:7b`'s A1 answer. **These are estimates to help the team choose a rule and two settings, not results.** Reported numbers must come from the test set through the running cascade.

Reference on the tuning set: `qwen2.5:7b` alone 80/98 = 81.6%; mean A1 single-request latency 2.84 s.

**Reading the tables:** *Esc* = escalation fraction. *Δ overall* = simulated accuracy minus the top model's on the same tickets (the limit allows −10). *Worst category* = largest per-category drop vs the top model (the limit allows −15). *Est. mean s* = mean over tickets of the A1 single-request latency of every model call that ticket would make (no queueing): small model (+ second small model for agreement) on every ticket, plus the top model on escalated tickets; for the length rule, long tickets make only the top-model call. The cascade is only faster than the top model alone when *Est. mean s* is below the top model's.

## Caveats

- Tuning set is small (98 tickets; Debt collection has only 6), so differences of a few tickets are noise.
- Latency estimates use A1 accuracy-run latencies (one request at a time, one model loaded). The A2 speed test measures the real figure under load.
- The A2 per-category limit is measured on the test set, where Mortgage (9) and Credit card (7) are small.
